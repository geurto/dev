# Personal Nix development environment

A self-contained development environment for Linux. Provides a custom Neovim setup with multi-language LSP/debugging, terminal tools (zsh, tmux, fzf), and optionally a full desktop environment (i3, polybar, alacritty).

## Prerequisites

Install Nix (if not already present):
```bash
sh <(curl -L https://nixos.org/nix/install) --daemon
```

Then copy the Nix config to enable flakes and the Nix command:
```bash
sudo cp nix/nix.conf /etc/nix/nix.conf
sudo systemctl restart nix-daemon
```

## Ubuntu setup

The `ubuntu/install.sh` script handles system-level dependencies that are not managed by Nix: the i3 window manager, polybar status bar, alacritty terminal, and associated configs. It also installs Rust via rustup, Docker, and the GitHub CLI.

```bash
bash ubuntu/install.sh
```

This will:
- Install build essentials, clang, gdb, cmake, Python 3
- Install Rust (via rustup), Docker, GitHub CLI, Firefox 
- Build and install i3lock-color from source
- Install alacritty and stylua via cargo
- Symlink i3, polybar, and alacritty configs to `~/.config/`
- Create `/opt/bin/zsh → ~/.nix-profile/bin/zsh` so alacritty can find the Nix-managed zsh without hardcoding a username

After running `install.sh`, install the Nix-managed dev tools:
```bash
nix profile install .#neovim .#terminal-tools
```

This makes `nvim`, `zsh`, `tmux`, and `fzf` available as normal user commands, with all LSPs, debuggers, formatters, and shell configuration included.

### Nerd font
Download the JetBrains nerd font at `https://www.nerdfonts.com/font-downloads` and install by putting it in `~/.local/share/fonts/`.

## NixOS setup

The `nixos/` directory contains a home-manager configuration that consumes this flake as an input.

```bash
cd nixos/
sudo nixos-rebuild switch --flake .#<hostname>
```

The NixOS setup pulls in:
- Neovim with all plugins and dependencies (from `inputs.dev`)
- Terminal tools (zsh, tmux, fzf) via the shared `lib.makeTerminalConfig` exported by this flake
- Ghostty terminal (Everforest Dark Hard theme)
- Build tools: gcc, cmake, ninja, python3

The terminal configuration in `nix/terminal-tools/config.nix` is the single source of truth shared between the Ubuntu profile install and the NixOS home-manager config.

### LUKS full-disk encryption

If the root filesystem is on a LUKS-encrypted partition, `hardware-configuration.nix` (generated by `nixos-generate-config`) should already include the correct `boot.initrd.luks.devices` entry. Verify it looks like:

```nix
boot.initrd.luks.devices."luks-<uuid>".device =
  "/dev/disk/by-uuid/<uuid>";
```

### Encrypted swap

If a swap partition also exists and is LUKS-encrypted, use `randomEncryption` rather than referencing the mapped device directly. This avoids a boot-time timeout caused by systemd waiting to unlock the swap container. In `hardware-configuration.nix`:

```nix
swapDevices = [
  {
    device = "/dev/disk/by-partuuid/<swap-partition-partuuid>";
    randomEncryption.enable = true;
  }
];
```

A fresh random key is generated on every boot, which is appropriate for swap (its contents do not survive reboots regardless). No `boot.initrd.luks.devices` entry is needed for the swap partition.

Note: the device must be identified by `by-partuuid`, not `by-uuid`. The LUKS UUID is erased on each boot when the partition is re-encrypted, making `by-uuid` invalid. The PARTUUID (GPT partition table identifier) is stable. Find it with `lsblk -o NAME,UUID,PARTUUID`.

## Running neovim without installing

To try neovim without installing anything:
```bash
nix run --extra-experimental-features "nix-command flakes" github:geurto/dev
```

## Running neovim in a Docker container

To use neovim inside a Docker container for debugging, mount the config directory:
```bash
docker run -it --privileged --net host \
  -v <DEV_ROOT>/nvim-config/:/root/.config/nvim/ \
  -v /usr/bin/nvim:/usr/bin/nvim \
  <DOCKER_IMAGE> bash
```

## Terminal tools

The `terminal-tools` package bundles zsh, tmux, and fzf with a shared configuration (aliases, starship prompt, Everforest-themed FZF, tmux keybindings). It is designed to run alongside a system-installed terminal emulator (alacritty on Ubuntu, Ghostty on NixOS).

The hybrid approach (system terminal + Nix-managed shell tools) avoids two known pain points:
- **nixGL**: required to run GPU-dependent apps from Nix on non-NixOS, but causes issues launching GUI apps from the terminal
- **home-manager on Ubuntu**: tends to conflict with system packages when working on projects with system dependencies
